## 二、四条知识主线（实测支撑）

### 1. 默认档位：不同能力的「出厂配置」不同

- FS 工具在**默认层**（Harness 的 Context Engineering 离不开它）；规划在**条件层**（有代价，按需开）——v0.7「更轻、更可配置」的实证
- `TodoListMiddleware` 做三件事：注入 `write_todos` 工具 + `todos` 状态字段 + 规划引导提示词；来自 `langchain.agents.middleware`，不是 deepagents 包
- `write_todos(todos=[{content, status}])` **整表覆盖**写；status 仅 `pending / in_progress / completed`

### 2. 锚点机制：状态流转与「重新注入」

- 接力棒节奏：状态更新发生在两次实际工具之间；串行时一步一更新，**并行批次下会合并 completed**（执行层 ≠ 规划层）
- `result['todos']` = 最后一次快照，state 无历史；查进度读 state、审计过程看消息轨迹
- **todos 幸存靠的不是记忆，是每轮重新注入**：摘要删得掉消息历史，删不掉提醒——3 次压缩后零迷路、零重规划（Step 5）
- token 曲线形状 = 压缩的心电图：单调上涨=无压缩，锯齿=压缩按周期工作

### 3. 验收分层：completed 是标记，产物才是证据

- `completed` 是 Agent 自己写的标记 ≠ 交付验收；验收条件必须从**用户目标语句**推导，不能用代理指标（「gamma 在文件里」≠「整行替换成功」）
- 双层判定：**策略层**（失败→取证→换策略→命中）与**目标层**（意图达成）是两回事；「自救成功」≠「任务完成」
- 目标验收薄弱是跨场景常量：模型按「我的动作成功了吗」自评，不按「意图达成了吗」自评——真正解法是把确认做成机制（ch09 `interrupt_on` / HITL），不是指望自觉
- 病根归因（单一变量实验）：错误来源决定中段行为——规格冲突 → 服从字面上报；环境陷阱 → 诊断重试自救

### 4. 成本结构：三层账本

| 层 | 指标 | 实测发现 |
|----|------|----------|
| L1 | 工具调用数 | 最粗糙；规划组可能反而更少（批量写 vs 全量读回） |
| L2 | 模型轮次（AIMessage 数） | 并行批量化压轮次；B 组 3 轮完成 8 次调用 |
| L3 | token（每轮输入=累计上下文） | **总账**：规划提示词是**固定税**（首轮 +~1250 tok）× 每轮重付 × 轮次乘数；`write_todos` 快照+回显是双份 payload（~150 tok/次） |

- 成本结论是**任务相关**的：文件大→读回贵；提示词税→恒定按轮收——「规划按需开启」的定量版
- 盲区警告：摘要器自己的调用不进 usage 账——账本只记看得见的轮次
- 规划在对照实验中买到的唯一硬通货：结构化 `result['todos']`（产品状态协议，research 前端 Todo 卡片读的就是它）

## 三、方法论收获（比结论更可迁移）

1. **判定器体检**应成为实验前固定动作——本章判定器三次翻车：①条目数盲区（漏内容级修订）②无路径序列+调用数当账本 ③代理指标当验收
2. **物证 vs 证言**：FINAL 是模型的证言，args / usage / state 是物证；判定只能下到证据支持的层面，不可判定就明说
3. **测量 > 故事**：step4 的小样本故事被 step4b 仪表证伪；单次样本不下结论，推断要写明前提才能被证伪
4. **判定条件是合取的**：不能凭单个显著特征 pattern-match（step3c 误判 A 的教训）
5. **用户对判定的质疑是最高优先级证据**：step3c 的上诉直接改写结论，暴露的是判定者而非被判定者
6. 预测三坑：无证据翻供 / 层次混淆 / 继承他人证言

## 四、经验教训速查

- 改 `.env` 类配置后重启长驻服务（Task 0 遗产，本章未踩）
- `repr()` 是不可见字符的唯一可靠取证手段；「看起来对」和「repr 对」是两回事
- 最短 old_string = 「保证命中」与「精确意图」的折中——真实代码编辑「改不干净」类 bug 的来源
- 外推曲线前先确认「机制配置是否相同」（P4 锯齿 vs 单调上涨）
- 实验材料先在本机版本核实 API 签名（`TodoListMiddleware` 的包归属随版本漂移）
